### v1.5.10 — «НЕРОВНЫЕ ОКОВЫ» (по фидбеку: «рандомные ауры тумана у всех подряд карт», «мигание карт убери», «перерисуй цепи — несколько цепей, по-разному натянутых») ✅

- **ЦЕПИ — НЕСКОЛЬКО НИТЕЙ, ПО-РАЗНОМУ НАТЯНУТЫХ.** Расположение прежнее
  (урок v1.5.8 не отменён): оковы лежат на ОБЩЕМ краю двух соседних карт
  (только шов, по 7px на карту) и СКРЕПЛЯЮТ карты ПОПЕРЁК шва. Изменился
  образ: вместо плотной лестницы одинаковых колец (читалась решёткой) шов
  держат 3 ОТДЕЛЬНЫЕ короткие цепи на высотах ~25/50/75% кромки, между
  ними чистый стык. У каждой нити своя натяжка — тугая (почти прямая),
  средняя, слабая (провисает дугой): у вертикального шва нити висят вниз,
  у горизонтального слабые бортают вбок. Порядок натяжек и сторона
  прогиба детерминированы координатами шва — поле выглядит живым, но
  стабильным (без рандома от перерисовки).
- **ЗВЕНЬЯ ПО ДУГЕ, НИТЬ — ОДИН СПРАЙТ.** Звено — маленькое кольцо с
  двенадцатью готовыми поворотами (шаг 30°); звенья идут по квадратичной
  кривой нити, ориентация чередуется (плашмя/боком, боковые мельче —
  видны с торца) и разворачивается по касательной — читается настоящей
  цепью. Вся нить ЗАПЕКАЕТСЯ в один спрайт 30x30 (генератор рисует те же
  звенья по той же кривой): на шов 3 картинки вместо 15 отдельных звеньев
  в DOM; металл по-прежнему ГЛУХОЙ (alpha=255, проверено по спрайтам),
  без растяжений и pattern’ов. Итог на поле 9x9: 348 <image> в SVG против
  ~928 у v1.5.9.
- **ПРОБЛЕСК ВДОЛЬ НИТИ — НА fx-КАНВЕ.** Свет бежит по каждой нити от
  карты к карте, перетекая с нити на нить: drawUgLink отдаёт ломаную
  вдоль дуг (с прогибами), fx.js рисует мягкое пятно (glint_pale.png /
  фиолетовый glint_royal.png у особых связей: royal — Владыка, lich —
  Пакт, big — Скованный, mult) на уже идущем канве частиц; полупрозрачен
  только свет; фаза детерминирована координатами шва. Выбор носителя —
  по замеру: SMIL на 100+ элементах (animateMotion / animateTransform /
  даже animate x+y) ронял кадр до ~27fps, канва держит 59-60fps в тех же
  условиях — быстрее, чем v1.5.9 с её 432 SMIL-плитками (~45fps).
  Мёртвое звено не светится вовсе; faded гасит свет (α .4); тумблер FX
  отключает проблески вместе с остальными эффектами.
- **ТУМАН АУР — ТИХИЙ И ПОСТОЯННЫЙ.** Зоны зданий больше не пульсируют и
  не «дышат»: сняты auraPulse/fogBreath/lichPulse/lichBreath и класс
  aura-live, который включал/гасил туман при срабатываниях зданий —
  именно он выглядел как случайные ауры на чужих картах. Зона теперь —
  статичный маркер области эффекта (цвета, границы и сила свечения
  прежние). Бонус: updateFxLive больше не пересобирает карту аур каждые
  250мс.
- **МИГАНИЕ КАРТ СНЯТО.** cardBreath (sp-live: каждая карта с активной
  особенностью дышала яркостью +25%) удалён совсем — активность показывает

### v1.5.9 — «РАЗГРУЗКА КУЗНИ» (максимальная оптимизация: игра лагает, особенно на демонах — по фидбеку игрока) ✅

- **ЧТО БЫЛО.** Профиль на густом поле демонов 7×7 (32 карты): тик углей
  demonEmberTick давал кадр-фриз 18-21мс логики + до 116мс худшего кадра:
  полный ребилд DOM поля (renderGrid 13-16мс, пересоздание всех карт с
  картинками и слушателями), полный ребилд SVG-связей с layout-thrashing
  (drawSynergies 9-11мс — getBoundingClientRect на каждое звено), лишний
  полный ребилд коллекции (не менялась!), updateHUD писал в DOM каждый кадр
  (pity/эпоха/кнопки — innerHTML 60 раз/с), канвас Арены создавал 3-4
  градиента на каждый кадр в двух канвасах, движок ритуала культистов
  пересчитывался на каждом кадре.
- **ИНКРЕМЕНТАЛЬНЫЙ РЕНДЕР ПОЛЯ.** У каждой клетки — сигнатура состояния;
  перерисовывается только изменившаяся клетка, причём при сохранной
  структуре обновляются только тексты бейджей и классы (доход, угли ◆,
  ▲/▼, HP-полоса) — без пересборки DOM и перезагрузки спрайтов. Разметка,
  классы и слушатели — байт-в-байт прежние. CSS-анимации клеток больше не
  рестартуют при каждом тике (побочный бонус: пропало «мигание» аур).
- **drawSynergies БЕЗ LAYOUT-THRASHING.** Спецификации связей собираются
  одним проходом без layout-чтений; если связи не изменились — SVG не
  трогается вовсе (SMIL-проблески не рестартуют). При реальной перерисовке
  все прямоугольники читаются одним проходом (один forced layout вместо
  десятков). Порядок звеньев сохранён (вниз → вправо, как у getNeighbors).
- **ЛИШНИЕ РЕБИЛДЫ УБРАНЫ.** Тики демонов/зверей/Балрога больше не
  перестраивают коллекцию (инвентарь они не меняют; при превращении демона
  — перестраивают, редкий случай). Слой знамений — по сигнатуре.
- **HUD С ДИФФОМ.** updateHUD пишет в DOM только изменившиеся значения
  (кэш последних строк): pity, кнопка Эпохи (--pct, cost), цены круток,
  applyFeatureLocks — по сравнению с состоянием. Числа на экране те же.
- **КАНАВ АРЕНЫ.** Статика боя (фон + тени «дорог») запекается в офскрин
  канвас один раз; туман — предзапечённые спрайты того же градиента;
  виньетка — кэшированный градиент. Превью армий строится по ключу
  (волна/отряд), а не каждый кадр; иконки отряда в доке — по сигнатуре.
- **РИТУАЛ КУЛЬТИСТОВ.** Движок ритуала пересчитывается при пересчёте
  дохода (10 Гц и при любом изменении поля) вместо каждого кадра; шкала,
  бейджи ⚡ и статистика читают всегда свежий движок.
- **ЗАМЕР ПОСЛЕ** (headless, то же поле): тик демонов 18-21мс → ~2-3мс
  логики; renderGrid 13-16мс → 0.8-4мс; drawSynergies 9-11мс → 0.03мс
  (пропуск неизменных связей); updateHUD −50% времени; худший кадр 116мс →
  83мс, кадров >100мс — ноль, доля «долгих» кадров −78%. Игровая логика,
  баланс, экономика и все случайности — без изменений.
- **РЕГРЕСС-ТЕСТЫ:** DOM-диф оригинала и оптимизированной версии на
  одинаковых сценариях всех 4 фракций (Э5 + Э3) — клетки, SVG, коллекция,
  HUD и доход байт-в-байт идентичны; то же после трёх тиков демонов с
  засеянным ГПСЧ (взрывы/превращения) — идентично. Функциональный прогон:
  расстановка, удаление, стек, тултипы, крутки, арена (бой идёт), ритуал
  (заряд и выплата), сохранение; консоль чиста. Версии ?v=1.5.9
  (анти-кэш), футер/flavor.
